# RC MetaStudio native round-three re-audit — 14 October 2026

## 1. Executive summary

Round three repairs the serious report/figure relationship failures identified in the [14 October baseline](../2026-10-14-reaudit/REPORT.md). HR/IRR omission rows retain the correct study identity; copied and exported reports retain clinical identity and table rows; fixed models omit τ² and inactive estimators. Subgroup tables contain fitted k, heterogeneity and existing prediction intervals. Round bubble ticks, zero-bound presentation and collapsed-axis guards work on the inspected paths. The new sequential null reference introduces a footer collision in the default MD cumulative figure (R3-01, medium).

This independent review changed only audit documents, replay scripts and screenshots. It began at `71342ad` on `ux/audit-improvements`. The visible app used Linux `xcb`, `DISPLAY=:0`, Qt 6.11.1/PyQt 6.11.0 and pinned R 4.6.1. [PROVENANCE](PROVENANCE.json) verifies all 55 receipt-bound source files and 24 installed RCMetaR files, with no mismatch. Doctor passed. Subsequent commits contain audit material only; application, test and R source remain unchanged.

Verdicts **relative to the 14 October re-audit**: **68 inherited IDs: 4 fixed, 7 improved, 55 unchanged, 2 regressed**. The ten additional baseline IDs (R2-01..R2-03 and F01..F07): **6 fixed, 1 improved, 3 unchanged, 0 regressed**. Already-fixed baseline findings are counted as unchanged when their fix is retained, so these counts deliberately differ from the baseline's original-defect scorecard. There are two confirmed new **medium** regressions: R3-01, sequential null references cross footer text; R3-02, six-decimal linear bubble ticks collide with their metric label. There are also newly observed **high** F10 (duplicate-name subgroup weights) and two **medium** issues: F09 is annotation overlap in six-decimal raw-data standard forests; F08: the BMJ entered-effect axis says **Mean**. Its label path existed in baseline source; introduction by round three is not established. No wrong fitted estimate/CI was established, but F10 confirms wrong displayed subgroup weights.

The main remaining work is semantic clarity and reading effort: named test nulls, calculator density, small type in long figures, standalone outcome/exposure context, residual package printouts and current help. This review recommends improvements to existing workflows only.

## 3. Regressions introduced by round three

### R3-01 — Medium: the new sequential null reference crosses the statistical footer

The [native MD cumulative figure](screenshots/matrix-twoarm-mean-cumulative-figure.png) draws its dashed zero reference through the model heading, Q line, overall-test line and prediction-interval text. The reference belongs to the plotted estimates; it should not run through prose. The corresponding [report](screenshots/matrix-twoarm-mean-cumulative-report.png) has the same values without that interference.

**Principle:** separate data marks from explanatory text. **Recommendation:** bound the line vertically to the plotted study/summary rows while retaining the in-range 0/1 policy. Verify the actual default cumulative/omission figures and exports, including an explicit range that excludes the null. Do not remove the useful reference or change any fit. Baseline source returned NA for these sequential references; round three enabled them through `rcmetar.metafor.refline`, establishing the new trigger. The inspected ordinary MD fixture shows the collision without an extreme-scale input.

### R3-02 — Medium: six-decimal linear bubble ticks collide with the metric label

The [entered-effect regression figure](screenshots/matrix-generic-effect-meta-regression-figure.png) places 0.400000 and 0.600000 tick strings across the vertical Entered effect label. The [coefficient regression view](screenshots/matrix-reg-coef-meta-regression-figure.png) exercises the same linear-axis path. These are supported precision settings, not extreme numerical inputs.

**Principle:** meaningful precision must remain readable. **Recommendation:** remove meaningless trailing padding from round linear ticks, and reserve measured left margin for the remaining labels before placing the metric title. Keep requested estimate/interval precision and real tiny values. Baseline `rcmetar.draw.metafor.bubble` capped axis digits at three; round three replaces that cap with selected precision and draws horizontal custom ticks. That source change, plus the native collision, establishes the new precision trigger. OR/PLO round display ticks are a successful repair and should be retained.

All three round-two regressions are closed on the inspected paths. Interrupted or failed verification attempts below are reported separately and are not automatically product regressions. A cross-platform screenshot difference alone is also insufficient.

## 4. New and remaining findings

### F08 — Medium: BMJ generic entered-effect axis loses its context

The BMJ collapsed-range entered-effect figure has **Entered effect** in its result identity and estimate headings, but **Mean** under the x-axis. Default and RevMan preserve the contextual heading. The [native BMJ precision view](screenshots/precision-05-round3-degenerate-axis.png) reproduces it; the original helper capture independently shows the same discrepancy. This is not a wrong fitted value, but a standalone figure can misstate what its numbers represent.

**Principle:** preserve metric identity across representations. **Recommendation:** use the existing contextual metric label for the BMJ axis, including entered-effect and regression-coefficient contexts. Preserve an explicit investigator-supplied axis label. Check the real result and exported plot across all three styles; no new analysis is needed. Source comparison shows the BMJ direction/axis label path already existed at `e64695b`; no old native BMJ capture was available to prove when users first saw it.

### F09 — Medium: six-decimal raw-data forests overlap weight and estimate fields

The [native sensitivity figure](screenshots/matrix-diagnostic-standard-figure.png) and [specificity figure](screenshots/matrix-diagnostic-standard-figure-1.png) overlap the percentage weights with the estimate/CI strings, including the bold overall row. The [one-arm proportion standard figure](screenshots/matrix-onearm-proportion-standard-figure.png) also overlaps these fields. Binary and MD/SMD standard views show the same problem, with touching raw mean/SD columns in the continuous layout. Raw TP/FP/FN/TN remain readable, and the [report](screenshots/matrix-diagnostic-standard-report.png) contains the correct values. SVG text nodes retain those same numbers; correct strings alone do not establish legible output.

**Principle:** preserve a readable separation between numerical fields. **Recommendation:** measure and reserve both annotation blocks for the selected precision, including diagnostic raw-column layouts and the pooled row. Verify real native views and exports at three and six decimals. The baseline's three-decimal native image is clear and the current three-decimal helper also separates the fields. There is no same-precision old native image, so introduction by round three is **not established**. The round-three sparse entered-effect spacing check does not cover this diagnostic layout.

### F10 — High: duplicate study names receive the wrong subgroup weights

In the [native subgroup close view](screenshots/weights-irr-subgroup-middle.png), Jaeger et al. 2001 and 2005 both receive **2.3%**. The [overall row](screenshots/weights-irr-subgroup-bottom.png) totals **98.3%**. The standard figure assigns the second study **4.1%**. These are nine included studies, not a rounding loss or an omitted-study display.

[WEIGHTS.json](WEIGHTS.json) independently reconstructs IRR effects from the saved original event counts and catheter-days using public `metafor::escalc`, then fits DL with `metafor::rma.uni`. It agrees with the displayed pooled estimate (0.6787009692), but gives weights **2.3472592135%** and **4.0584402623%**, summing to **100%**. The subgroup renderer uses `match(flat.names, om.data@study.names)`, which returns the first duplicate for both Jaeger rows. The missing 1.7112 percentage points explain the 98.3% total. This mapping also existed in baseline source, so it is an uncovered pre-existing path, not a round-three introduction.

**Principle:** study identity must survive reordering. **Recommendation:** carry the original included-row index or stable study ID through subgroup ordering and use it for weight lookup. Do not require investigators to rename valid repeated-author studies. Check each plotted weight against an independent overall fit and require complete totals. Keep fits, estimates and CIs unchanged. The audit fixture's name-keyed covariate assignment gives both Jaeger studies category A; the saved input makes that exact grouping explicit and replayable.

### Remaining F04/R05 precision path — Medium

The [coefficient standard forest](screenshots/matrix-reg-coef-standard-figure.png) still prints **1.110223e-16** as Fixture 2's lower bound, although its retained input is zero. The baseline identified this same row. The targeted zero-bound probe passes, but does not close the original path. `rcmetar.draw.revman.study.effect.labels` formats each estimate/bound separately, so its default tolerance scale is that individual value rather than the row's estimate/CI magnitude. Carry the established row scale through that existing renderer path while preserving real tiny rows. This is an unfinished baseline finding, not an additional new ID.

### F05 — Medium: name the tested null and scale

Diagnostic/single-arm figures still present an unqualified overall-effect test. Name the actual fitted null and transformation, or de-emphasize that line when it has limited clinical relevance. Keep the fit unchanged; do not invent a clinical threshold. Sensitivity/specificity estimates and uncertainty should remain primary.

### F06 — Medium: simplify the active calculator layout

Older binary/continuous calculators retain dense modes, abbreviated labels and small scroll-dependent actions. Show only the active input mode, use existing arm names and reserve space for the estimate/primary actions. Fresh Linux grid evidence does not reproduce the old Windows preference-dependent category-width case; do not close that part without a retained-settings drive.

### F07 — Low: finish terminology and task help

Use Numeric/Category consistently with existing guidance, Automatic instead of [default], and the contextual estimate label in CSV/calculators. Update Quick start for Tables, copy/CSV, Change settings and sequence versus display order. Retain supported import aliases internally.

### Statistical and aesthetic assessment

The retained sequential estimates/CIs and subgroup/standard fitted statistics agree across views, with the explicit displayed-weight exception F10; subgroup and standard heterogeneity checks use independent public fits. Six-study two-arm fixture totals remain 135/147, with binary events 39/51. Formatting a representational zero does not erase genuine tiny effects. Fixed-model assumptions are now distinguished from estimated random-model heterogeneity. The report serializer preserves relationships instead of flattening rows.

Round ticks and in-range nulls are clearer, but long HR forests remain small at Fit width and require scrolling. Selected six-decimal runs are deliberate precision probes, not a recommendation for publication defaults.
